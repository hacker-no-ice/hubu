# Break Hubu: v0.2.4

**All claims are about Hubu's own ledger and records, not provider invoices.**

Four experiments ran against unchanged released Hubu: real CLI/HTTP server,
fresh SQLite, synthetic external-executor receipts. No provider was called or
paid. Gongbu, Temporal, MCP transport, provider adapters and real billing were
not tested. The matching dark website route is `/break-hubu/v0.2.4`.

## Observed results

| Claim | What happened | Verdict |
| --- | --- | --- |
| [Runaway](../ep01-runaway/README.md) | Ten one-cent settlements consumed USD 0.10. All 100 further attempts were budget-denied without a token or hold. Final frozen/remaining/unaccounted consumption: zero. | **Holds** within the fixed configuration |
| [Last cent](../ep02-last-cent/README.md) | Normal settlement rejected USD 0.03 against USD 0.01 authorized while the lease was active; the hold remained. After expiry, owner reconciliation recorded USD 0.03 once, exposed USD 0.02 overrun, and left USD −0.02 remaining. All 11 new probes were denied. | **Holds with caveat:** explicit owner reconciliation is required |
| [Crash recovery](../ep03-crash-recovery/README.md) | SIGKILL terminated the owned Hubu process after a public claimed/held checkpoint and durable synthetic billed marker, before settlement. The one-cent obligation survived restart/expiry; ordinary settle/release were rejected after expiry. Owner resolution, retry and a second restart retained one one-cent posting. | **Holds** at this process-crash boundary |
| [Many clients](../ep04-many-clients/README.md) | Ten processes made 100 three-cent attempts: 33 allowed, 67 denied, zero unresolved. USD 0.99 stayed held until the burst finished. Then 33 settlements consumed USD 0.99, leaving USD 0.01, no hold and no unaccounted consumption. | **Holds with caveat:** the release serializes TCP handling |
| Runtime/thread-bound identity | Documentary known gap: the normal bearer selects an owned account without authenticating which runtime/thread may use it. No identity experiment was run for this card. | **Does not hold in v0.2.4**; planned for v0.3 in [HUB-162](https://linear.app/hubu/issue/HUB-162/bind-agent-account-use-to-an-authenticated-agent-session) |

The released [account resolver](https://github.com/hacker-no-ice/hubu/blob/5344ab565171e1aa3d3ec628641cdbfce18372af/crates/hubu-api/src/lib.rs#L6084-L6120)
checks ownership and active status, without runtime/thread-bound authority.
Other owners' accounts are rejected; the gap is authority within that owner.

**The bearer boundary applies to every row.** The same normal bearer accesses
protected budget/policy administration in the released
[HTTP routing code](https://github.com/hacker-no-ice/hubu/blob/5344ab565171e1aa3d3ec628641cdbfce18372af/crates/hubu-api/src/lib.rs#L1953-L2042).
The kits fix those settings; they do not show that a bearer holder cannot raise
the budget. Executor-scoped authority is tracked in
[HUB-32](https://linear.app/hubu/issue/HUB-32/issue-executor-scoped-hubu-capabilities-for-gongbu).
Process separation does not establish server-enforced roles.

## Reproduce

Follow the [prerequisites and cleanup instructions](../README.md). Use the kits
commit, not the older release checkout or an installed binary:

```sh
git clone https://github.com/hacker-no-ice/hubu.git
cd hubu
git checkout f280b3dc9488040ff9e6ea9b7b42e3447f7b1021
./break-hubu/run-all.sh --release v0.2.4
```

Or select one bounded experiment:

```sh
./break-hubu/ep01-runaway/run.sh --release v0.2.4
./break-hubu/ep02-last-cent/run.sh --release v0.2.4
./break-hubu/ep03-crash-recovery/run.sh --release v0.2.4
./break-hubu/ep04-many-clients/run.sh --release v0.2.4
```

Run-all retains failures and continues. Exit 0 means supported runnable claims
with caveats; 1 means a contradiction; 2 means incomplete without a demonstrated
contradiction. Missing evidence cannot pass. A contradiction survives a later
missing step. The documented identity gap stays visible regardless of these exits.

## Interpretation limits

- The fixture catalog label is `executor:gongbu:image`, but the Python fixture
  performs the HTTP calls. No Gongbu process runs.
- Last-cent/crash owner resolution is an explicitly labeled simulation of the
  human-authorized API path, using known synthetic evidence and a distinct
  capability retained in the parent. It does not establish automatic invoice
  ingestion or autonomous judgment about a real charge. Negative remaining
  balance after a confirmed overrun is truthful accounting.
- Crash recovery covers one public protocol checkpoint and the exact owned Hubu
  process. It does not cover internal commit faults, disk/power loss, lost
  responses, Gongbu/Temporal recovery or provider-side deduplication.
- EP04 uses the released [serial connection handler](https://github.com/hacker-no-ice/hubu/blob/5344ab565171e1aa3d3ec628641cdbfce18372af/crates/hubu-api/src/lib.rs#L152-L164).
  Obligations accumulate without settlement/release during the burst; that
  monotonic workload and the public checkpoint support the admitted total.
  This does not establish simultaneous database writers, fairness or throughput.
- Task quality, hostile-executor truthfulness, external invoices, direct-provider
  bypass prevention and every possible attack remain outside these results.
  macOS is qualified; Linux/Windows were not qualified by this card.

This is the first card; no previous-card comparison exists. No new product
failure was observed in these four runs; the known identity/bearer gaps remain
visible above. Future releases follow the [manual checklist](../release-checklist.md),
without adding a PR proof-kit CI gate.
